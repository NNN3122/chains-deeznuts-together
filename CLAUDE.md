# CHAINS DEEZNUTS TOGETHER — project guide

Read this before touching anything. It captures the full vision so every session builds toward the same game, and the rules that keep the codebase coherent.

## What this game is

A 1–6 player online co-op horror-comedy. Players are physically chained together and must cooperate to climb upward through stacked horror levels and escape at the top. The tone is chaotic and stupid-funny, but the horror is real: tense atmosphere, monsters that kill you, and lots of jump scares. The rhythm is: scream, then laugh.

- **Camera:** toggle first-person / third-person at any time (key V).
- **Chains:** physics-based. One player falling, jumping, or panicking pulls the others. Falling drags teammates down. Dying sends the whole group back to the last checkpoint. Chain topology changes with player count (line, ring, pairs).
- **Levels, stacked vertically (bottom to top):**
  1. Liminal yellow office maze — buzzing fluorescents, shifting layouts, an entity you hear but rarely see.
  2. Abandoned pizzeria — possessed animatronic mascots; manage doors, cameras and power while climbing.
  3. Infected rooftop city — rooftop parkour; slow infected by day, fast lethal hunters at night.
  4. Haunted manor grounds (Ashgrave Manor, the user's call on 21 Oct) — a foggy walled estate at night; repair four engines to power the main generator and open the escape gate while the Groundskeeper hunts you. (The seductive hotel with the succubi, below, now comes after it.)
  5. Seductive hotel — dim luxury; succubi lurk (see Enemies).
  6. Final mashup ascent — every zone remixed, ending in a boss chase to the exit.
- **Items ("go stupid with it"):** random loot. Guns (pistol, shotgun, ridiculous oversized weapons), bombs and sticky explosives (hurt monsters and teammates alike), energy drink (speed boost, jittery screen, then a crash), jetpack (lifts the whole chain, hard to control), grappling hook, flashlight, flare gun, decoy noisemaker, and a rare **Transformation item** that turns a player into an original superhero archetype (bald one-punch hero, speedster, flying strongman) or an animal (snail: slow, sticks to walls; bird: flies but weak; cat: silent, lands on feet, nine lives). Transformations affect the whole chained team in funny ways (a bird trying to carry five people).
- **Enemies:** every level has its own monster plus roaming threats. Items can fight, stun, distract, or help escape them. Monsters react to noise. Boss encounters end select levels.
- **Succubi:** from a distance they look like friendly women calling for help; when a player gets close they transform into demons and attack. Observant players can spot subtle tells (glitchy audio, wrong reflections, flickering or wrong shadows). Strictly non-explicit: the horror is the betrayal and the transformation.
- **Horror:** scripted jump scares plus randomized/procedural scares so repeat runs stay unpredictable. Proximity voice chat later; monsters hear player noise (including microphones, eventually).
- **Originality:** all characters, monsters, heroes, mascots and names are original designs. Never copy or name existing franchises or characters in code, assets, or text.

The full game design document is `design/GAME_DESIGN_DOCUMENT.md`. Treat it as the reference for names and numbers; this file is the short version.

## Engine and architecture rules

- **Godot 4.3+ with GDScript** (developed and tested on 4.7.2). Static typing everywhere. Tabs for indentation.
- **Multiplayer:** Godot high-level multiplayer. Solo uses `OfflineMultiplayerPeer` (same server code path, no sockets); co-op uses `ENetMultiplayerPeer`. **Host-authoritative:** the host (peer 1) simulates all bodies, the chain, items, monsters and triggers; clients send input by RPC and render replicated state. Built for 6 players; never special-case "2 players".
- **Assets:** CC0 textures live in `assets/textures/` with their sources in `assets/textures/LICENSE.md` (ceiling tiles and carpet from TextureCan, mapped in world space by `LevelKit` shaders, carpet recoloured blue to mustard; the manor's twelve 1K sets from ambientCG in `assets/textures/manor/`, see "The manor's real surfaces and moving fog"). Everything else is built in code: shader materials (`LevelKit`), primitive models (`PlayerModel`, `ItemModels`), synthesized sounds (`Sfx`), system fonts (`UiTheme`). Only download new assets with the user's explicit OK, CC0 or similar only, and record each one in the LICENSE file. Texture imports: VRAM compressed, mipmaps on, normal maps flagged as normal maps.

- **Items are data-driven:** adding an item = one `.tres` in `src/items/data/` + one logic script + a model case in `ItemModels`. Nothing else changes. An item that should pour into another (ammo) implements `merge_into(player)`. Dropped pickups keep `carry_state()`.
- **Levels are generated from a seed** so every peer builds the identical world before connecting. Replicated props need identical node names on all peers. The seed is the host's: `Net.world_config` ({seed, arena, horde}) is random from the title (`Net.random_world_config`) and `YellowRooms.DEFAULT_SEED` 1931 from the command line (`--seed=N` overrides; the tests rely on the fixed one). A joiner builds the default world, connects, and sends its config in `register_player`; a host with a different config answers `_rpc_wrong_world` and drops it, and `Main._on_world_mismatch` tears the world down, rebuilds with the host's config and joins again (once). This keeps the rule that the world exists before any replication traffic. The office layout, the pizzeria's dressing and the Lot's crowd all take the seed. A joiner's console shows a few harmless "Node not found ... /Sync" errors in the second before it rebuilds (the host's synchronizers name nodes the default world doesn't have). Nothing in the office hunts by noise any more, so the noise meter is a "they'll come and look" meter there. Monsters that stun answer `stun(seconds)`; the flashlight burn checks live in each monster. Level 1 must not be crouch-walkable (the user's second playtest): the Hires patrol the route (`YellowRooms.patrol_cells`; Hire 0 of each floor is the `sentry` for the last three route rooms, the rest pick route rooms 65% of the time), end walks with a 2.4 s `SWEEP` through 180 degrees, and a fresh sighting calls the floor (`YellowRooms.hire_callout` -> `HollowHire.join_chase`); loud events call `wake_floor(i, pos, seconds)` -> `alert`, which makes them hunt the nearest player's room with sharper eyes for that long. Every floor forces noise and running (`_build_events`): `StuckDoor` on a bridge doorway of B4's and B1's route (opens only to a body over 5 m/s, bang = noise 100 for 3 s, wake 14 s), `AlarmPull` on B3 (the lift's `PressurePlate.enabled` is false until it's pulled: hold Ctrl 0.6 s; klaxon and floor strobe 40 s, wake 40 s), `TimedHatch` over B2's shaft (release switch two rooms back, open 25 s, slams unless a body is in or at the hole), and the B1 ambush (`_tick_ambush`: first player into the elevator room, a Hire is placed in the last doorway and screams; the car's inside is `is_safe_spot`). A squeaky decoy is heard floor-wide and a Hire stands over it sweeping until it stops. Darkness: office ambient 0.045, troffers 0.85, 44% of ordinary tubes flicker/dying/dead, auto-exposure max 105; `lights_out` is 1.4 s gutter + 12-20 s dark; `_tick_stutter` blacks out the Line's floor 12-20 s every 60-90 s (not mid-chase); `LightController.floor_stutter`, and tubes registered `safe` (Break Rooms) never black out. Blasts kill monsters on their own floor only.
- **Level 2 rules:** `Pizzeria.nearest_node` prefers a node in the position's own room over a closer one through a wall, and Pappy's Step goes round by the graph when the nearest player is behind a wall (he used to stand at the wall forever). Pappy is host-authoritative like the Custodian: `watched` (any player's view cone + line of sight, or a live desk whose camera covers his node) freezes his Step timer; Steps teleport him one graph node toward the nearest player, never seen moving. At 0% every pizzeria light is out and Pappy steps every 3 s regardless of eyes. Monsters that hunt a player expose `hunt_peer` and sit in group "monster" (Hires also keep group "hire", Launchers "launcher", Pappy "pappy").
- **The horde (`src/enemies/horde/`, group "horde", not "monster"):** a crowd is arrays, not nodes. `Horde` keeps up to 2000 agents in packed arrays (x, z, y, velocity, yaw, walk phase, state, kind) and steps them in one loop on `HordeField`, a flow field on a 1 m grid rebuilt in slices (a few hundred cells per tick, breadth-first flood then per-cell gradient directions, swapped in whole) toward every chained body and anything loud (a decoy). Separation runs through a spatial hash; crowding lifts an agent (`climb`) so a wall of bodies climbs itself. Every agent moves and animates every tick (slicing the mass to a third per tick made the crowd step at 20 Hz, which the user saw as lag); LOD: the nearest 250 to the Line are "active" and recompute separation every tick with claws, lunges, hands on the chain and shootability; the mass recomputes separation a third per tick and reuses the last push. The walk cycle follows ground covered, with a floor of 70% of the meant pace so a pile pressed against a wall keeps working its legs; heading turns at 5 rad/s, never snaps; the shader adds TIME-driven sway, head twitches, a limp for some, and arms up (custom.z + 2) for active agents within 3 m. Rendering is one MultiMesh per kind (`HordeMesh`: Roach, Weaver, Flitter, all original mutations; `Horde.FLYING` kinds skip walls and the climb, circle at `FLY_HEIGHT` over the nearest player and dive (`DIVE_*`), never grab the chain, and are hit at `HIT_HEIGHTS` per kind) whose vertex shader animates limbs from the mesh's limb tags (UV2, CUSTOM0/1 pivots) and four floats of INSTANCE_CUSTOM (phase, seed, tint, state); the whole buffer is written once per tick. The seed also gives every body its own build (length, width, leg length, head), a limp for some, and its own chitin hue, so no two in the swarm match. Hits are capsule overlaps against players, never physics: at the edge of a crowd the claws shove you out, three sets of hands on one player for 2.5 s is a layoff. Hands on the chain: an active agent within 1 m of a segment hangs on, each holder takes 30% of both ends' speed (`Player.hold_drag`, set and consumed per tick), three stop the team; a body over 4.6 m/s (a sprint with one holder, a slide), the chain snapping taut (`ChainSystem.jerked`) or the air horn fling them off; the Snubby asks `Horde.hit_ray` before the physics ray so a round drops the nearest active agent; bombs call `blast`. Rooftops: `HordeField` cells are FLOOR (with a ground `height`), WALL or VOID (the street; `fill_void` then `set_floor_rect` per roof), walkers stand on their cell's height and can't take a step up over 0.6 m (a pile can climb over a low one), and `CLIMBER` kinds (Weavers) climb a higher roof's face (`CLIMB`, `CLIMB_SPEED`) or, at a VOID edge, look across with `floor_ahead` and swing over on a thread (`SWING`, drawn as lines from `swing_anchor`; clients replay swings from snapshots). With no field under them (the Line is on another roof) climbers head straight for the nearest player and roaches mill. A walker more than `LEFT_BEHIND` 110 m from every chained body goes back into the walls (GONE, server-side, carried to clients by snapshots), so the swarm left on crossed roofs costs nothing. `MAX_AGENTS` 2400. Net: the server sends the active set at 10 Hz (8 bytes per agent, the far half every other send) plus 48 of the mass round-robin, unreliable; clients run the same mass from the same spawn seed and their own field and correct toward snapshots. Every level that hosts a horde builds the field (`block_box` for walls) and spawns with a fixed seed on every peer.
- **The slide:** sprint (over 4.5 m/s) then Ctrl in `Player._tick_normal`: capsule to crouch height, 8.4 m/s decaying on a square curve over 1 s, no steering beyond a nudge, ends standing if there is headroom and Ctrl is up, else crouched. `SFLAG_SLIDING` drives the pose, the camera dip and tilt, and the scrape sound on every peer. A slide under a Launcher's jump counts as a dodge, and throws horde holders off the chain.
- **Physics layers:** 1 world, 2 chain bodies (players, Ballast), 4 thrown, 8 monster hitboxes. Areas that detect players use mask 2.
- **Server-only logic** is guarded by `multiplayer.is_server()`; anything clients see is pushed with `call_local` RPCs or replicated properties.
- **Autoloads:** `GameState`, `Net`, `ScareDirector`, `Voice` only. `Voice` needs `audio/driver/enable_input` (project.godot) and does nothing headless or solo.
- **The user plays over TeamViewer.** TeamViewer sends a held key as a stream of taps and breaks captured mouse look. Movement must never depend on mouse capture; keys are bound by physical code AND key label; Remote Controls mode (auto-on when TeamViewer is running or key flicker is detected) holds keys for 650 ms after each tap. Its mouse look hides the cursor and confines it to the window (`MOUSE_MODE_CONFINED_HIDDEN`), with no button to hold: plain movement turns the view, and holding the cursor in the outer 7% of the window keeps turning, since a remote cursor stops at the edge of the user's own screen. The user rejected right-drag look ("like all games"); don't bring it back. Arrow keys walk/turn and R toggles auto-walk in every mode.
- Keep the chain central: a mechanic, item or level piece that would play the same without the chain is wrong for this game.

## Running and testing

- Double-click `PLAY.bat` or the desktop shortcut. `PLAY 2 WINDOWS (co-op test).bat` opens a host and a client side by side. `RUN TESTS.bat` runs the smoke tests.
- **Sharing with friends:** `MAKE FRIEND ZIP.bat` runs `tools/make_friend_zip.ps1`. It writes `CHAINS DEEZNUTS TOGETHER - send to friends/` on the Desktop:
  - the zip: the official Godot exe renamed to `CHAINS DEEZNUTS TOGETHER.exe`, a `.pck` of the same name (Godot auto-loads it), READ ME and LICENSES;
  - the bare `.pck`, for updates;
  - `HOW TO SEND.txt`.

  The pck comes from `--export-pack "Windows Desktop"` (`export_presets.cfg`), which needs no export templates. `script_export_mode=0` keeps scripts as text so `Net.get_build_id()` (a SHA-256 of `res://src/**/*.gd`) matches between source and pck; joiners with another build are turned away with a message. Keep `.bat` files CRLF.
- **GitHub:** public repo `NNN3122/chains-deeznuts-together`, pushed with the user's `gh` login. `PUBLISH UPDATE TO GITHUB.bat` runs `tools/publish_release.ps1`, which builds the friend zip, commits and pushes, and creates release `vN+1` with the zip as `CHAINS-DEEZNUTS-TOGETHER.zip`. Friends use `releases/latest/download/CHAINS-DEEZNUTS-TOGETHER.zip`, the link at the top of README. The repo is public: never commit real IP addresses, emails or anything else personal. Commits use the GitHub noreply email (local git config).
- **Invites:** hosting (not headless) runs `PortOpener`, which uses UPnP on a thread: discover, add a UDP mapping with a 4 h lease renewed hourly, then query the public IP. The mapping is removed on leave and quit. `InviteCode` turns the public IPv4 into a 7-character base-32 code (`XXXX-XXX`, plus `-PORT` when not 7777). The JOIN box accepts a code, a pasted message containing one, `IP[:port]` or a host name. Never let tests touch the router: `Net._begin_invite` skips UPnP when headless. Fallbacks shown in the Esc menu: LAN and Tailscale addresses (Tailscale is installed on the user's PC).
- **New `class_name` scripts:** run `godot --headless --path . --import` once so the global class cache knows them, before a plain headless run.

## Conventions

- One class per file, `class_name` for anything referenced by type. File names in `snake_case`, class names in `PascalCase`.
- Signals over polling for UI; polling is fine inside physics ticks.
- Constants for tunables at the top of each script with a short comment on the unit (meters, seconds, m/s).
- Comments explain intent and gotchas, not what the line does.
- Keep `CLAUDE.md` current when the architecture or status changes.
